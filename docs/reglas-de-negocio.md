# Reglas de Negocio del Sistema Lumiere

Este documento consolida las reglas de negocio que el sistema Lumiere cumple hoy en su rodaja vertical, indicando su descripción, su implementación en el código y las pruebas automatizadas que las verifican.

---

| Código | Regla de negocio | Dónde vive en el código (Archivo y Función) | Prueba que la verifica |
|---|---|---|---|
| **RN-01** | **Obligatoriedad de datos de reserva:** Para reservar un boleto, los campos `funcion_id`, `asiento` y `nombre_cliente` son obligatorios y no pueden ser cadenas vacías ni contener solo espacios en blanco. Si falta alguno, se rechaza la operación lanzando `DatosInvalidosError`. | `lumiereApp/backend/src/domain/cinema.ts`<br>`ReservarBoletoUseCase.ejecutar()` | `lumiereApp/backend/src/tests/domain.test.ts`<br>• `datos vacíos lanza DatosInvalidosError`<br>`lumiereApp/backend/src/tests/adaptadores.test.ts`<br>• `datos vacíos lanza DatosInvalidosError` |
| **RN-02** | **Exclusividad de butaca por función (no sobreventa):** Una misma butaca no puede ser reservada más de una vez para la misma función. La verificación preventiva en el caso de uso y la restricción atómica `UNIQUE (funcion_id, asiento)` en base de datos rechazan duplicados lanzando `AsientoOcupadoError`. | `lumiereApp/backend/src/domain/cinema.ts`<br>`ReservarBoletoUseCase.ejecutar()`<br>`lumiereApp/backend/src/infrastructure/postgres.repository.ts`<br>`PostgresBoletoRepository.guardar()` | `lumiereApp/backend/src/tests/domain.test.ts`<br>• `asiento ocupado lanza AsientoOcupadoError`<br>`lumiereApp/backend/src/tests/adaptadores.test.ts`<br>• `asiento ocupado lanza AsientoOcupadoError`<br>`lumiereApp/backend/src/tests/e2e.test.ts`<br>• `POST /api/reservas rechaza asiento ocupado con HTTP 400` |
| **RN-03** | **Independencia de asientos entre distintas funciones:** Un mismo asiento (por ejemplo, `A1`) puede ser reservado en funciones distintas sin generar conflicto ni bloqueo. | `lumiereApp/backend/src/domain/cinema.ts`<br>`ReservarBoletoUseCase.ejecutar()` | `lumiereApp/backend/src/tests/domain.test.ts`<br>• `mismo asiento en distinta función procede sin conflicto`<br>`lumiereApp/backend/src/tests/adaptadores.test.ts`<br>• `mismo asiento en distinta función no colisiona` |
| **RN-04** | **Identificador único y marca temporal inmutable:** Toda reserva confirmada genera un identificador UUID v4 único y registra la fecha/hora de creación (`reservadoEn`). | `lumiereApp/backend/src/domain/cinema.ts`<br>`Boleto.crear()` | `lumiereApp/backend/src/tests/domain.test.ts`<br>• `reserva exitosa crea un boleto con datos correctos` |
| **RN-05** | **Traducción determinista de colisiones a HTTP 400:** Ante colisiones de concurrencia o validaciones fallidas, el controlador traduce limpiamente las excepciones a respuestas HTTP 400 con `{ status: 400, error: '...' }`, impidiendo fallas 500 o fugas de excepciones de base de datos. | `lumiereApp/backend/src/presentation/reservas.controller.ts`<br>`ReservasController.ejecutar()` y `reservar()` | `lumiereApp/backend/src/tests/domain.test.ts`<br>• `asiento ocupado devuelve status 400 y mensaje de error`<br>`lumiereApp/backend/src/tests/e2e.test.ts`<br>• `POST /api/reservas rechaza asiento ocupado con HTTP 400` |
